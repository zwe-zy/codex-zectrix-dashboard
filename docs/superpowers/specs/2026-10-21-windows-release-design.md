# CODEX 指示牌 Windows 发布版设计

目标是让 NOTE4 用户从 GitHub Releases 下载 Windows 程序后，按照简短中文说明自行完成配置并长期使用。先完成 Windows，保留以后支持 Linux 和 macOS 的代码边界。本轮不发布其他平台的可用性承诺。

## 用户操作

1. 从 Releases 下载 Windows x64 ZIP，解压后双击主程序。
2. 程序检查本机 Codex 是否可用、账户是否登录，并把程序安装到当前用户的固定目录。
3. 在本机窗口输入 ZECTRIX API Key，选择设备和页面，预览并确认首次上传。
4. 选择是否登录后自动启动，配置成功后立即在后台运行；关闭配置窗口不影响刷新。
5. 再次打开主程序时，显示中文菜单：查看状态、重新配置、启动、停止、自动启动设置、卸载。

采用简单的中文终端向导，避免为首版增加完整图形界面或额外运行时。用户不需要安装 Rust、Python 或 Node.js。用户仍需要自己可用的 Codex 登录状态、NOTE4 和极趣云账号。

## 本轮范围和交付

- Windows x64 是本轮发布目标。Windows 11 为本机验收环境；Windows 10 的支持范围只按实际构建与验证结果填写，不先宣称支持。
- 交付源码改动、回归测试、Windows ZIP、SHA-256 清单、中文 README、发布说明和 GitHub Actions 工作流。
- 本地生成可审阅的发布候选版本。GitHub 发布前再确定目标仓库，避免修改原作者仓库或发布到错误账户。
- 保留 MIT LICENSE、原作者署名和来源，记录 Windows 改动。发布包不包含个人配置、日志、设备标识或密钥。

## 安装与后台运行

程序与数据放在当前用户的 LocalAppData 下，程序文件与配置、日志分开。用户移动或删除下载的解压目录，不影响已安装版本。产品身份固定如下，显示名称变化不能改变这些标识：

| 用途 | 固定值 |
| --- | --- |
| 数据根目录 | `%LOCALAPPDATA%\CodexZectrixDashboard`，保留现有设备配置位置 |
| 已安装程序 | 数据根目录下的 `app\<version>\`，每个版本包含配套的两个 EXE |
| 当前版本记录 | 数据根目录下的 `installation.json`，带独立格式版本 |
| 凭据 service | `com.barrybarrywu.codex-zectrix-dashboard` |
| 凭据 account | `zectrix-api-key` |
| 新版自动启动项 | `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 中的 `CodexZectrixDashboard` |
| 需识别的旧计划任务 | `Codex ZECTRIX Dashboard`，同时核对当前用户和完整执行路径 |

自动启动采用当前用户的 HKCU Run 注册项，不依赖需要管理员权限的计划任务。默认安装不触发 UAC。注册带引号的绝对路径，校验完整命令长度不超过 260 字符；路径不适用时明确报错，不写入无效启动项。登录后启动允许 Windows 的调度延迟，不承诺登录瞬间完成。设置自动启动失败时，保留已成功保存的设备配置，显示清楚的原因和手动启动入口，不让用户重新输入 Key。[Microsoft Run 注册项说明](https://learn.microsoft.com/en-us/windows/win32/setupapi/run-and-runonce-registry-keys)

后台增加以当前用户和正式数据目录为范围的单实例保护。所有新版共用同一范围，锁不能包含版本号。反复点击启动、登录启动与手动启动同时发生时，只保留一个刷新实例。安装、配置提交、升级、卸载另有共享操作锁；启动也检查维护状态，避免维护中途被登录启动重新拉起。锁和进程状态必须区分“确认不存在”和“无权检查”。

启动、停止、更新和卸载只操作本产品拥有的进程；不按通用进程名批量结束 Codex。停止操作优先让后台完成当前写入并退出；超时后必须核对进程身份，无法确认时终止本次变更并报错，不能继续替换文件。

首版只提供用户下载新 ZIP 后运行的本地升级，不增加在线自动更新服务。将新版本准备到独立版本目录，校验版本、目标平台和配套文件的 SHA-256；校验和用于发现损坏和混包，不当作发布者签名。

升级事务顺序为：取得操作锁 → 校验并准备新程序 → 暂停启动入口并确认旧后台退出 → 备份允许恢复的非密钥数据及版本、启动项记录 → 迁移数据 → 启动并检查新版本 → 提交当前版本及启动项。普通程序升级不更换凭据 service/account，也不改写 Key。

数据快照覆盖 `settings.json`、publisher/runtime 状态及新版本引入的持久文件。旧版不认识的格式不能直接交给旧程序。每种持久格式有版本和迁移规则；缓存只在明确可再生成且不会误导显示时清空。失败时先确认新版退出，再恢复旧程序引用、旧版可读的数据和原启动状态。

事务记录只保存阶段、文件引用和版本，不保存 Key。启动时发现未提交事务，先恢复到可确认的一致状态；恢复失败则保持后台停止并显示修复入口，不盲目运行两个版本。本地健康检查要求新进程就绪、读取配置及凭据成功、能够持久化状态；云端断网或 Codex 暂不可用作为单独数据源故障显示，不据此反复回滚程序。

卸载取得同一操作锁，停止本产品后台、移除其启动入口，并询问是否删除密钥及本地数据。只删除安装清单明确归属本产品且解析后仍在目标目录内的文件；不递归清理用户下载目录。

旧版迁移单独处理，因为 0.1.9 不遵守新版的锁。顺序固定为：核对旧任务所有者及所有执行动作 → 停用旧启动入口 → 确认旧后台退出 → 备份并迁移数据 → 验证新版 → 提交新入口。不能只凭任务名认定归属。

停用任务需要管理员确认时，仅为这次旧版迁移提示；拒绝、权限不足或后台无法确认退出时，新版不得启动或启用 Run 项，不修改旧数据，并恢复已改变的旧启动状态。若恢复也失败，明确显示旧后台当前状态和恢复步骤，不能报告迁移成功。新版完成验证后再清理旧任务。新用户不创建此计划任务。

## 配置与故障提示

- API Key 继续保存到 Windows 凭据管理器，输入不回显，不出现在命令行参数、配置文件或诊断导出中。
- 区分未找到 Codex、未登录、额度接口不兼容、云端网络失败、密钥被拒绝、没有兼容设备、上传被拒绝和自动启动失败。
- 多设备选择显示可辨认的设备名称；不足时在本机显示设备标识用于区分，不写入公开日志。
- 默认打开程序即进入向导或菜单，保留原命令行接口，窗口内报错后可读且可重试。
- 首次测试画面明确标为测试，避免把固定示例额度当作当前额度。
- 配置成功后启动后台并检查进程存活、额度读取和上传状态。网络延迟时显示等待或失败，不提前宣布全部完成。

### 重新配置的提交规则

输入和选择阶段保留原服务。用户取消时不修改既有配置。正式提交前取得操作锁、阻止新的后台启动，并确认旧后台退出，随后再发送需要用户确认的测试画面和保存新配置。

设备、页面、Key 与该路由的发布状态作为一个逻辑变更处理：旧路由的图片去重和上传时间不得复用到新设备。提交成功后按原运行状态或用户本次选择启动后台，检查其已加载新配置；失败则恢复旧配置和旧运行状态。对远端已成功显示的测试图无法本地撤回，提示中必须说明，不能声称“所有操作均未发生”。

Key 的正常失败回滚快照仅保留在内存并及时清除，不落入磁盘事务记录。若进程在凭据与文件提交之间异常终止，不能保证内存快照仍在；下次启动根据未提交记录阻止后台自动上传，进入恢复向导，必要时要求重新输入 Key。不能在凭据和设备对应关系不确定时擅自恢复发送。

自动启动设置是设备配置之后的独立步骤。仅这一项失败时不回滚已经成功的设备和凭据配置，提供手动启动以及重试设置入口。

### Codex 发现与恢复

向导、状态菜单和后台使用同一套发现与兼容性检查。首版支持原生 Windows Codex；WSL 和远程电脑不在首版范围。优先检查用户明确指定的可执行文件，再检查 Desktop 安装目录，最后检查 PATH；所有候选均验证文件存在及协议能力，不因版本目录名较新就认定可用。

以当前用户身份使用其 Codex 登录环境，不读取其他 Windows 用户的认证，也不代用户静默改变账户。诊断在本机显示选中的程序位置，并区分程序不存在、未登录、API Key 登录不提供订阅额度、协议不兼容等情况。自动检测不能悄悄切换到另一个自定义账户目录。

持续复用一个 app-server 会话。程序路径因 Codex 升级失效时先回收旧进程树，再重新发现并按退避策略连接；用户明确指定的路径失效时提示修正，不静默改用另一账户环境。传输中断和单个能力不可用分别处理，不能每次轮询都重启进程。

## 正确显示任务和额度

### 任务观察的证据与降级

任务查询明确指定目标来源，首版候选来源为 `cli`、`vscode`、`appServer`，不依赖 thread/list 的默认来源过滤。目标 Desktop 版本实际使用的来源须在发布验证中确认，不能仅凭枚举名称推断。顶层任务须有受支持的父子关系字段作证据；字段缺失或来源未知时提示能力受限，不将子任务或未知任务算作已完成。[Codex App Server 官方文档](https://learn.chatgpt.com/docs/app-server)

对每个支持的 Codex 版本记录三种独立验证：额度字段、顶层任务枚举、运行和结束状态。接口返回 supported 只代表调用可用；必须另做 Desktop 发起任务、运行、正常结束、失败、中断的同步实测。独立 app-server 无法证实某项跨会话状态时，该能力显示兼容性提示，不恢复到猜测状态；额度继续工作。

空闲显示“空闲”，未加载显示“状态未知”，不直接认定为“已完成”。“本轮结束”、失败或中断必须有受支持的最新执行记录；不读取或保留提示词、回复及工具参数来猜测结束。验证只保证本机受支持来源，不能宣称覆盖云端所有任务。

汇总优先显示经验证的运行状态，其次是有可靠事件时间的近期失败、中断和本轮结束。结束类提示仅在对应事件后 24 小时内显示，缺少可靠事件时间时不为历史记录重造“刚刚发生”的时间。存在无法观察的任务时保留兼容性提示，不能根据其余空闲任务推断所有任务已结束。子任务不重复计数。

### 额度组与窗口

首版只显示 `codex` 额度组，并标明范围。有有效的 `rateLimitsByLimitId.codex` 时使用该组；该组缺失时，只接受 `limitId` 明确为 `codex` 的 legacy 结果，或已经纳入兼容性验证、字段中没有组标识的旧版单组响应。不能任取其他模型组，也不能用旧缓存将不同账户或额度组混合。[Codex App Server 官方文档](https://learn.chatgpt.com/docs/app-server)

先选择目标组，再解析窗口，避免无关组的新增或异常字段拖垮有效数据。组存在但某窗口格式错误时逐窗口降级，不用另一套 legacy 响应悄悄覆盖错误。分别保留 primary、secondary 的数值、时长、重置时间、观察时间和可用性；一个有效窗口不因另一个异常而消失。明确不存在的窗口不显示；暂时读取失败的窗口可保留已知值并标记过期。

按实际 `windowDurationMins` 标注“5 小时”“每周”或实际时长；缺少时长显示“窗口未知”，不按 primary/secondary 猜测。支持有限的小数百分比，拒绝超出 0–100 的值；缺失重置时间只使重置时间未知，不抹去有效比例。读取失败不能显示为零额度。

保留 400×300 黑白拼贴风格，为两个额度窗口调整布局。任务观察每 60 秒、额度观察每 600 秒；任务 180 秒、额度 1800 秒未成功刷新时显示过期标记。继续使用内容变化触发上传和至少 60 秒的上传间隔，不引入每分钟强制刷新。

### 上传状态与时间

分别记录数据观察时间、真实内容画面成功时间和最近一次 HTTP 上传成功时间。前两者按清楚的标签展示；最近 HTTP 成功时间仅用于诊断，不参与画面变化判定。观察时间按轮询推进也不得单独触发上传。屏幕中的更新时间指最近一次真实内容上传，不声称代表设备已刷新。

保留纯时间补图机制：补图可显示前一次真实内容成功时间，但不能再次推进该时间。仅最近 HTTP 成功时间随补图更新，因此不会生成无限补图。

发布状态持久化内容来源类型（测试或真实）以及不含上传/观察时间的归一化内容指纹。首次真实数据、重启期间内容变化，或新设备配置必须按内容变更处理，不能继承为旧的纯时间补图。旧版状态无此指纹时不能判断内容未变，升级后保守生成一次真实内容更新，再进入正常去重。密钥和任务正文不进入指纹或发布状态。

上传成功仅表示云端接受；设备显示是否更新仍需实机确认，不虚构设备回执。

## 工程和发布

共享 Rust 核心继续处理 Codex 观察、数据归一化、渲染和云端上传；Windows 安装、进程控制、凭据和自动启动放在平台边界内。维持一个持久 app-server 会话，复用既有重连与退避机制，不为每次刷新启动一个新会话。

这项 Windows 独立 ZIP 分发方案补充并改变 ADR 0001 中“仅通过插件安装”的约束，需要新增 ADR 说明 Windows 分发选择；不删除原 macOS 插件能力。系统凭据存储和 Rust 预编译程序的原决策继续保留。

GitHub Actions 增加 Windows 测试与发布包验证。提交和 PR 做检查，版本标签生成候选 ZIP 与校验清单，发布到 Releases 使用明确的发布步骤。使用 Cargo.lock 构建并核对源码、版本和包内容；实际凭据和实体设备不进入 CI。

实施分三阶段：先完成普通权限安装、后台控制、配置事务、旧版迁移和恢复；再修正任务与额度及上传状态；最后做打包、独立安装和实机验收。完整图形界面、在线自动更新和其他系统发布不加入本轮。

## 验收条件

1. 普通用户首次安装，无管理员提权，无需开发环境；中文和带空格路径可用。
2. 首次配置、取消、错误 Key、断网和重试均可恢复；自动启动失败不丢配置。后台运行时换设备、换页面和换 Key 后，旧后台不得继续发送；凭据提交中断时进入恢复向导而非自动上传。
3. 配置结束立即后台刷新，关闭窗口后继续运行；重复启动不产生多个上传进程。旧任务停用失败、UAC 拒绝、旧进程无法退出时，新版不能同时运行。
4. 单窗口、双窗口、多额度组、小数、无效旁支和缺失字段逐窗口验证；任务状态须完成 Desktop 同步实测，缺失能力独立降级。检查 400×300 画面无裁切、重叠和错误窗口标签。
5. 重启、登录启动、休眠唤醒、断网重连和 Codex 升级导致路径变化后恢复；不遗漏当前账户约束，无后台进程或 app-server 泄漏。登录启动允许系统调度延迟。
6. 升级保留设置和凭据身份；覆盖文件占用、新程序启动失败、迁移后失败以及事务中断，确认旧版恢复后仍可读取其数据。卸载不会误删其他目录或结束其他 Codex 会话。
7. Windows 的格式检查、静态检查、完整测试和发布包冒烟测试通过；在本机 NOTE4 验证实际画面。
8. 一名未参与开发的使用者可以只按 README 完成配置；在获得这一独立验收前，不宣称已完成新用户易用性验证。
9. 测试图转真实内容、停机期间内容变化、纯时间补图分别验证；真实内容时间正确推进，HTTP 时间独立记录，纯补图不会无限触发新上传。
10. 从实际下载的 ZIP 验证安装流程，记录签名、SmartScreen 和杀毒软件提示；不能用本地构建文件的体验代替下载包体验。尚未完成的外部环境验收须在候选版说明中列出。

## 当前证据与实施前提

现有 Windows 版已在本机成功读取 Codex 额度并更新 NOTE4。已复现普通权限创建计划任务遭拒绝，以及首次配置后不立即启动后台的问题。源码确认单窗口额度、空闲与未加载映射为已完成以及缺少后台单实例保护。

已观察到从测试图转真实画面后的时间语义异常；实施前用恢复分类回归测试复现根因。纯时间补图不推进内容时间本身是有意行为，不作为笼统故障处理。尚未验证所有 Desktop 任务状态、所有账户额度组或新设计的真实运行行为。
