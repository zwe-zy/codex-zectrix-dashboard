# NOTE4 完整控制台设计

日期：2026-10-22。基线：Windows 0.2.0-rc.5，`3ed0b55ef25e9bf74b8abca5efb5b79c89868348`。

状态：用户于 2026-10-22 回复“继续”，已确认本文范围；进入实施计划编写，尚未开始产品代码改动。

## 一眼看懂

做一个中文桌面窗口，把原来的数字菜单变成按钮。左侧四个页面：**运行总览、墨卡与主题、设备配置、设置与诊断**。保留五种风格及五张自动更新；关闭窗口后后台继续工作。已有用户升级后沿用 Key、设备、主题和更新模式，新用户按向导完成配置。

本轮交付 Windows x64 图形版，继续提供无需安装 Rust、Python 或 Node.js 的完整 ZIP。界面技术支持后续移植；Linux/macOS 的安装、凭据、启动与实机验收安排在后续版本，不把框架支持等同于产品已支持。

## 已确认与设计默认值

- 已确认：完整控制台布局、Windows 优先、最终面向 Windows/Linux/macOS、GitHub 下载后简单配置、五种墨卡风格、单/双额度自适应、五张都能自动更新。
- 本轮默认：简洁中文界面，跟随系统明暗外观；窗口默认约 1040×760，较小时内容重新排布或纵向滚动；100% / 150% / 200% 缩放下可操作。
- 本轮采用一个常规桌面窗口。关闭窗口退出界面进程，独立后台继续运行；点击“停止后台”才停止更新。开机启动只启动后台，不强制弹出窗口。
- 轻量控制窗、托盘菜单、自定义布局编辑器和联网自动升级不纳入本轮。

## 四个页面

| 页面 | 用户能做什么 | 状态表达 |
| --- | --- | --- |
| 运行总览 | 查看实际额度、任务状态、选择墨卡大图、启动/停止后台 | 分别显示后台状态、数据读取时间、各页最近上传和失败情况；停止后台后标明“上次数据” |
| 墨卡与主题 | 查看五种主题，切换单页/五页模式，选择单页主题 | 五页固定为 1 怪盗、2 EVA、3 掌机、4 仪表、5 HUD；只预览图片不会修改设备 |
| 设备配置 | 使用已有 Key 或更换 Key，列出设备，选择设备与单页模式的目标页，查看测试图后提交 | 操作失败给出中文原因和对应下一步；未提交的编辑可取消 |
| 设置与诊断 | 开关登录启动、查看本地诊断、安装/升级、查看版本、卸载 | 安装与配置的结果分开显示，不把“配置已保存但启动失败”显示为全部失败 |

墨卡页分清“真实画面”和“示例布局”。示例可查看单额度 7 天、双额度 5 小时 + 7 天，始终标记为示例；实际额度窗口和时长以数据源为准，不按订阅名称或窗口数量推测。

五页模式使用固定映射，点某张卡只是选中预览。单页模式的主题变更有明确“应用主题”按钮。切换为五页模式时，确认区列出会替换的墨卡 1–5；切回单页时提示其他页保留最后画面。应用后继续遵守既有节流和设备同步周期。

## 首次使用与升级

1. 下载完整 ZIP，解压后双击 **NOTE4控制台.exe**。
2. 未安装时显示“安装并开始”，校验完整发布包后安装到当前用户目录；不要求安装开发环境。
3. 未配置时进入向导：检查 Codex 登录 → 填写 ZECTRIX Key → 选择设备和页面 → 查看测试图并确认上传。
4. 配置成功后启动后台，进入总览。首次启用五张模式仍通过明确的五页替换提示。
5. 已安装用户首先看到“升级”，成功后自动载入现有设置。旧后台原先运行时恢复运行，原先停止时保持停止。

Key 默认掩码输入，只存入既有 Windows 凭据管理器。选择“使用已保存的 Key”时，不将其取回到可显示的表单；换设备可在内部复用凭据。取消、完成和错误返回时清理临时密钥缓冲，不记录到日志、命令行参数、预览文件或安装快照。

耗时操作在工作线程执行，窗口保持可响应。同一时间仅执行一个修改操作，按钮显示具体进度。发现设备、编辑设置和生成本地预览期间可以取消；进入安装/配置提交阶段后，关闭请求等待该事务完成或回滚，再退出界面，避免主动制造半完成状态。

## 技术方案

采用 **egui / eframe 的 Rust 桌面界面**，直接调用现有 Rust 业务层。该框架提供原生桌面入口，并支持 Windows、macOS、Linux；这适合保留当前核心代码、减少两套业务逻辑。[官方项目](https://github.com/emilk/egui)、[eframe 原生入口文档](https://docs.rs/eframe/latest/eframe/)。具体依赖版本在实施计划中锁定并构建验证。

另两条路线是用 WebView 承载网页界面，或使用只面向 Windows 的界面技术。前者更便于复刻网页样式，但增加前后端通信与运行环境处理；后者会增加后续跨平台界面的重做工作。本方案选择 Rust 原生窗口，保留已选布局和交互，不承诺与网页预览逐像素相同。

中文字体随程序嵌入可再分发的字体及其许可证，不复制用户 Windows 系统字体；图像预览继续使用现有 400×300 渲染器。egui 支持嵌入字体与字体回退。[字体配置文档](https://docs.rs/egui/latest/egui/struct.FontDefinitions.html)。

结构分为三个部分：

- **界面层**：页面、表单、错误提示和图片显示，只处理界面状态。
- **桌面操作服务**：返回结构化结果，封装现有安装、配置、启动/停止、主题、墨卡模式与诊断功能。CLI 与 GUI 共用事务核心，不模拟键盘输入或解析中文控制台输出。
- **独立后台**：继续负责唯一的持续 Codex 观察会话、渲染、去重和上传。打开多个窗口不会产生多个上传后台；GUI 的状态查看不再创建持续 Codex 观察会话。

保留现有设置格式、凭据名称、操作锁、后台身份检查和版本检查。GUI 的任何修改操作都经过同样的锁与版本核对；旧窗口发现安装版本已变化时转为只读，并提示打开新版，禁止悄悄修改新版本配置。

## 真实数据与预览的一致性

当前文件只有上传指纹及时间，不能直接供 GUI 显示实际额度。因此由后台增加独立、有限大小、原子写入的 `desktop-status.json`，仅包含渲染所需的额度、固定任务状态、数据时间与旧数据标记，以及安装版本和设备配置指纹。不得包含任务标题、对话、Key 或原始 API 响应。

GUI 可见时约每 2 秒读取本地快照及后台状态；不改变额度每 10 分钟、任务每分钟的源读取周期。快照缺失、损坏、设备配置不匹配或来自旧版本时显示不可用；后台停止或数据超过既有新鲜度边界时，明确标为上次数据或已过期，不继续声称任务正在实时运行。

后台成功上传的 PNG 可缓存为五个固定页码文件。GUI 仅在 PNG 的 SHA256 与对应成功记录吻合时标为“最近成功上传”；否则显示当前数据预览或预览不可用。预览缓存写入失败不应把已成功的云端上传改判成网络失败；保留诊断并让界面显示预览不可用。缓存与日志一起遵守限定目录、大小和链接检查，卸载清理范围包含新增文件。

“上传成功”只代表云端已接收。没有设备侧确认数据时，界面不会显示“屏幕已刷新”或推测设备在线；统一提示“设备同步后刷新”。源状态、上传状态、物理显示状态分别表达。

## 发布、安装兼容与恢复

新增 GUI 可执行文件，保留现有 CLI 和后台文件名与命令，方便排错及兼容脚本。Windows 包包含三个程序、原许可证、第三方许可证说明、快速入门和校验清单；中文 GUI 入口与说明中的双击目标一致。

发布包清单升级为版本 2，并继续识别 rc.5 的版本 1 精确文件集合。不得简单扩宽为任意文件都可安装；两种格式分别校验允许的文件集合、大小、hash、平台与程序版本。升级、失败回滚、旧版恢复和卸载均覆盖两种格式。GUI 启动失败不等同于后台数据故障，启动错误应有可见说明及 CLI 排错入口。

安装后为当前用户创建开始菜单入口，以便移走下载目录后仍能打开控制台；只管理能确认归属本程序的快捷方式。创建入口失败单独提示，不把已经成功的设备配置丢弃。卸载使用现有延迟清理机制，先关闭受控程序后清理；未知文件或非本程序快捷方式不删除。

本方案明确补充 ADR-0010：Windows 首选入口由控制台菜单变为 GUI，发布包增加 GUI 和许可证文件。原有按用户安装、后台独立运行、凭据存储和跨平台验收边界继续有效；设计确认后在实施时补充对应 ADR。

## 故障与操作反馈

- 网络请求、设备发现、安装和启动有超时与具体失败结果；窗口不冻结。
- 连续点击不会重复启动后台或重复提交配置；互斥操作期间禁用相关按钮。
- 凭据被拒绝显示“需要重新配置 Key”，保留其他有效设置。
- 上传结果不确定与明确拒绝分开显示，不声称屏幕一定没有变化。
- 配置事务未完成、权限不足、磁盘写入失败、预览缓存不可用分别提示；沿用既有回滚与恢复能力。
- 卸载在界面中明确选择是否删除设置、缓存及 Key；查看诊断不自动上传文件或日志。

## 验收标准

1. 从完整 ZIP 双击 GUI 即可完成安装与首次向导；正常图形操作不弹黑色菜单窗口。
2. rc.5 升级后保留现有 Key、路由、主题、五张模式、启动设置和后台原运行状态。
3. 四个页面使用真实业务结果；五张墨卡及单/双窗口正常预览，布局不重叠，示例不会误标为真实。
4. 开关后台、应用主题、切换单/五页、查看诊断、取消配置和卸载均有清晰反馈；关闭 GUI 不停止后台。
5. GUI 查看状态不会增加持续 Codex 会话；只有一个上传后台，上传节流与重启恢复保持有效。
6. 旧快照、损坏快照、半完成事务、失效 Key、断网、保存失败与并发窗口有有意义的回归测试。
7. 原有全量回归、格式、静态检查、发布 ZIP 冒烟通过；额外核对包格式 v1/v2、中文路径、中文输入、字体、窗口缩放和版本升级回滚。
8. 本机验证真实五页上传及 GUI/后台独立生命周期；实体屏幕最终显示由设备同步后观察。未经实机验证的平台、环境和代码签名情况继续明确记录。
