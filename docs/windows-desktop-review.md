# Windows 控制台审阅与实施记录

范围：`65f71fc..a79bf1f` 的桌面控制台、共享事务、快照、安装与分发。按用户选择由主执行者实现，最后独立审阅一次。审阅发现 0 个 Critical、7 个 Important、0 个 Minor；本轮逐项核实并修复，不追加第二轮独立审阅。

| 问题 | 修复与证据 |
| --- | --- |
| 每两秒刷新使 Key 输入框失去焦点 | 区分本地刷新与前台操作，输入保持可用、动作仍串行。原生复现；真实 egui 事件测试先失败后通过。 |
| 清空的 Key 可被 Ctrl+Z 恢复 | 每帧清除密码控件的撤销历史；覆盖取消、移交、失败和保存完成四种生命周期。先失败后通过。 |
| 读取失败仍长期显示最新数据及后台运行 | 刷新错误单独返回，不取消输入草稿；撤销实时状态并继续按时间老化，成功后恢复。测试验证上次数据→过期及输入不丢失。 |
| 卸载中断后按钮不可用 | 区分待卸载记录，提供继续卸载入口；部分文件已删除时提示从完整 ZIP 重试。真实文件锁测试验证中途失败后可继续安全清理。 |
| 安装版本检查与事务锁之间存在竞争 | 将期望版本检查移到安装事务锁内；旧窗口不得覆盖另一窗口已安装的新版本。测试验证拒绝降级、零额外安装操作及锁优先。 |
| 第二额度过期却无提示 | 主、次额度分别计算并显示有效性，覆盖仅第二额度的情况。 |
| 单页模式漏报 Key 被拒绝 | 复用后台持久状态解码，识别两种拒绝状态；隔离测试先失败后通过，不读取真实凭据或访问云端。 |

实施裁量与边界：

- 复用现有独立开发克隆及分支，与原备份、生产安装分开。未再创建重复工作树。
- Windows 无 Bash，计划记录用 PowerShell 等价流程；任务简报、提交基线及验证日志保持可追溯。
- 中间任务使用针对性回归，交付前运行核心和 GUI 两套全量检查。避免重复检查未变化代码。
- Windows 凭据库初始化可失败，因此后台构造返回明确错误；显式登录检查可短暂连接 Codex，本地刷新不能启动观察会话。
- CLI 与 GUI 共享配置事务和卸载入口；GUI 延迟卸载使用校验过的 CLI 助手。界面模型独立于 eframe，便于测试。
- 中文字体设为常规字重，保留原始 OFL 字体文件及来源说明。
- 独立审阅没有执行生产升级或真实上传，后续由执行者完成。云端成功不能代表实屏已刷新。
- 原生窗口检查与无 GPU 的布局测试分别记录；物理 100/150/200% DPI、中文输入法完整组合、其他 GPU 初始化失败不因测试模拟通过而视作实机验收。
- 本轮只交付 Windows 候选版；Linux/macOS、代码签名和远端发布仍是后续范围。保留本地分支，不自动合并或推送原作者仓库。

最终测试、打包和生产检查结果见 [Windows 验收记录](windows-acceptance.md)。测试日志及含本机信息的运行记录保留在开发工作区之外的验证目录，不放入发布包。
