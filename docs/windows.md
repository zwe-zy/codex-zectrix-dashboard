# Windows 使用说明

本次候选面向 Windows x64 和 ZECTRIX NOTE4。以本机 Windows 11 验证为准，Windows 10 尚待实机验证。普通使用不需要编译环境。

## 安装与配置

先打开 Windows 版 Codex 并登录 ChatGPT。在 [极趣云](https://cloud.zectrix.com)的「开放 API」创建 ZECTRIX Key。Key 属于设备云平台，与 OpenAI API Key 不同。

将 Windows ZIP 完整解压到一个空目录，双击 **`NOTE4控制台.exe`**，点击“安装并开始”。在设备配置页依次检查 Codex 登录、粘贴 Key（或复用已保存 Key）、获取设备列表、选择页面、预览并确认上传。设备名后显示简短标识，Key 输入会遮挡。

安装把配套文件复制到 `%LOCALAPPDATA%\CodexZectrixDashboard\app\版本`。以后可从开始菜单搜索“Codex NOTE4”打开，下载目录可移走。程序使用当前用户的 HKCU Run 项开机启动；默认不要求管理员权限。只有迁移已核实身份的旧计划任务时，可能需要 Windows 授权停用它。

首次屏幕显示带“测试画面”字样的样张。后台读取成功后替换成真实信息，上传至少相隔 60 秒。不要把测试图上的百分比当成自己的额度。

## 图形控制台

控制台有四页：运行总览（额度、任务、后台、最近成功上传）、墨卡与主题（单张直接配置、多张拖动排序）、设备配置（检查登录、Key、设备及预览确认）、设置与诊断（登录启动、安装恢复、诊断、卸载）。关闭控制台不会停止后台；需要停止时使用总览按钮。

主题示例标明模拟数据，编辑和拖动不会上传；点击“保存并应用”才更新界面列出的墨卡。总览区分额度和任务各自的数据新鲜度，后台停止后显示最后已知值；只有图片 hash 匹配成功上传记录才显示真实预览。

原命令行程序仍保留，以下菜单说明供排错使用：

| 选项 | 用途 |
| --- | --- |
| 1 安装/升级 | 验证完整发布包并安装；已有配置会保留 |
| 2 配置/重新配置 | 更换 Key、设备或页面，确认前旧后台继续运行 |
| 3 启动后台 | 启动本地独立进程，重复操作不会产生两个实例 |
| 4 停止后台 | 等待本程序后台退出；屏幕保留最后画面 |
| 5 查看状态 | 查看版本、运行状态、开机启动和读取/上传时间 |
| 6 开关开机启动 | 启用或关闭当前用户启动项 |
| 7 卸载 | 停止后台并删除已核实的程序文件，分别选择是否删除数据及 Key |
| 8 切换主题 | 1 怪盗、2 EVA、3 掌机、4 仪表、5 HUD，0 取消；选择自动保存 |
| 9 墨卡模式 | 1 五张都自动更新（替换墨卡 1–5），2 只更新配置页，0 取消 |

关闭菜单窗口后，后台继续运行。安装路径和配置目录可包含中文、空格。不要在发布包目录放配置或日志，否则完整包检查会拒绝它。

## 切换外观

在控制台“墨卡与主题”页选择并应用（原 CLI 菜单 **8**）： **1 怪盗剪贴、2 EVA 机库终端、3 像素掌机、4 航天仪表、5 赛博 HUD**。五种主题都有单额度和双额度布局，按接口实际返回的窗口自动选择，不按 Plus/Pro 名称猜测。默认保留怪盗风。

选择“1 张”，直接选择设备墨卡编号和风格，点击“保存并应用”，不需要重新输入 Key。自定义排列保存在 `inkcards.json` 中；旧版的单页主题仍从 `appearance.json` 读取。保存会短暂重启原先运行的后台，原先停止的后台仍保持停止。NOTE4 按自身同步周期拉取画面。

未使用自定义排列时，命令行也可使用 `codex-zectrix-dashboard.exe theme pop-cut` （可选值：pop-cut、eva、pixel-console、space-gauge、cyber-hud）。自定义排列的主题请在图形控制台修改。旧下载包与已安装版本不一致时，请先选 1 安装/升级。

## 多张墨卡自动更新

在“墨卡与主题”页在顶部直接选择“2 张 / 3 张 / 4 张 / 5 张”，也可添加或移除卡片，每张独立选风格。抓住左侧“拖动”调整位置，或用“上移 / 下移”。从上到下对应设备墨卡 1–N；点击“保存并应用”后才更新设备。未保存时可撤销，状态刷新不会覆盖草稿。未选中的页面保留原图并停止自动更新。各页共用实时数据，自动适配实际单/双额度。

已有单页或固定五页配置可直接读取。保存新的自定义排列需要 rc.4 或更新版本。原 CLI 菜单 **9 → 1** 会恢复默认五风格顺序，**9 → 2** 会恢复旧配置页和旧预选主题；两者都会替换自定义排列。日常使用建议在控制台配置。

模式保存在 `inkcards.json`，五页上传记录保存在 `inkcard-state.json`。每页独立去重、限流及退避，失败的一页不会阻止其他页更新；Key 被拒绝则全部暂停，重新配置后恢复。原有单页状态格式不变，重新配置设备或成功提交新的配置会让五页重新上传。损坏的五页记录可通过菜单 9 重新选择模式修复。每张上传间隔至少 60 秒，一轮可能上传五张；不改变设备自身同步周期。

每张处理后立即保存进度，再处理下一张；重启会恢复各页的上传记录和等待时间。若本地进度无法保存，后台停止继续上传并记录诊断，恢复目录写入权限或可用空间后可重新启动。

命令行对应 `codex-zectrix-dashboard.exe inkcards all` 或 `inkcards single`。菜单 5 显示各页最近传图时间和连续失败数；五页模式的“最近内容上传”取五页中最早的成功内容时间，某页从未成功时显示暂无。

## 数据和时间含义

设备配置、非敏感状态和诊断日志保存在 `%LOCALAPPDATA%\CodexZectrixDashboard`。ZECTRIX Key 只保存在当前 Windows 用户的凭据管理器；升级快照不保存 Key。

额度读取的是 Codex 配额组，每个窗口独立验证、独立过期。接口明确移除窗口时清除旧值；某个窗口数据格式异常时保留其旧值并独立过期。窗口时长或重置时间缺失时显示未知，不臆造“5 小时/每周”。任务来源限制为受支持的顶层任务；看不到 Desktop 任务、缺少状态或没有可信结束时间时显示暂不可用。能看到部分任务时，会保留“运行中”等已知状态，同时显示“部分可见”，不代表全部 Desktop 对话的状态。

“最近额度读取”是获取额度成功的时间；“最近内容上传”是实际状态内容上传成功的时间；“最近传图成功”包括必要的时间标记补图。测试图不推进真实内容更新时间。额度读取周期为 10 分钟、任务为 1 分钟；额度 30 分钟、任务 3 分钟未更新会标记旧数据。

只有显示内容变化才上传。成功后最多补一张准确时间标记图，补图不会循环触发自身。网络断开时自动退避，恢复后继续；Key 被拒绝后需要重新配置，不会无休止重试错误 Key。

## 升级与故障恢复

下载新版本，解压到新的空目录，打开新版控制台并点击安装/升级。先校验文件 hash 和三个 EXE 的版本，再停止旧后台、保存非密钥快照并启动新版。本地就绪检查不依赖云端联网，所以临时网络故障不会不断回滚程序。

若升级中断，再次选择 1 会先恢复未完成的安装记录。若更换配置中断，界面会提示重新配置，期间暂停上传。一次上传已送到屏幕后，回滚本地配置不能撤回那张屏幕画面。

已完成的配置不会因为开机启动设置失败而丢失；可单独通过菜单 6 重试。未知的旧任务或来源不明的旧程序不会被自动结束；先核实并处理旧启动项后再安装。

如果检测到手动启动、没有受控身份记录的旧后台，会阻止安装，避免新旧版本同时刷新。已成功迁移的旧计划任务保留为禁用状态，迁移记录随安装事务提交；此后即使原下载目录被删除，也可继续升级。如果配置输入期间另一窗口完成升级，请重新打开配置向导，旧配置不会因此改变。

## 排错

| 提示/现象 | 处理 |
| --- | --- |
| 找不到 Codex | 安装并运行 Codex Desktop；程序会寻找它自带的 CLI，也支持 PATH 中的 codex.exe |
| 显式指定的 Codex 路径失效 | 修正 `CODEX_ZECTRIX_CODEX_BIN`；不会自动切换到可能属于另一账号的 CLI |
| 账号不可用 | 打开 Codex 并登录 ChatGPT 后再配置 |
| Key 无效或无设备 | 检查极趣云账号、Key 和设备绑定关系 |
| 上传结果不确定 | 先看屏幕，再检查网络后重试；本地不能撤回已经送达的画面 |
| 自动恢复未完成 | 保留本地数据目录，重新打开下载包选择安装/升级；配置中断则选重新配置 |
| 后台停止但屏幕有图 | 电子纸会保留最后画面，这是正常现象 |

给开发者反馈时，只提交程序版本、固定错误提示和复现步骤；先检查日志内容，避免提供 Key、设备完整标识和私人 Codex 数据。

## 发布范围

`0.3.0-rc.3` 是候选版，尚未代码签名。完整自动化测试、包内运行检查与真实设备验收分别记录。Windows 10、独立新用户、GitHub 下载的 SmartScreen 体验、登录启动和休眠唤醒不能由单机单元测试代替。Linux/macOS 的统一安装体验后续开展。

## Desktop 本地执行状态

在已验证的 Codex 0.163.0-alpha.10.2 中，独立 app-server 对另一进程中的活跃对话返回 `notLoaded`，其执行记录接口还可能把该轮呈现为无结束时间的 `interrupted`。rc.2 对 API 枚举出的顶层任务额外只读查询当前 Codex 主目录的 `thread_history_1.sqlite`，仅查询执行标识、状态和时间列，不查询任务正文、回复、工具参数或错误内容，不修改该数据库。SQLite 已静态编译进 EXE，用户无需安装额外软件。

运行中需 `inProgress` 及 3 分钟内的开始或活动时间；完成/失败/中断需真实结束时间，且仅展示最近 24 小时事件。旧执行状态、未来时间、未知数据库版本、读取失败不会被当作正常状态。长时间没有新活动记录也可能显示状态未知。此适配针对本机当前格式，Codex 升级改变格式后会降级提示，不承诺所有未来版本或云端任务可用。


## 安装包与快捷方式

新版 ZIP 为 schema 2，共七文件：中文控制台、原 CLI、companion、许可证、第三方声明、快速入门和 package.json。仍可读取旧 schema 1 五文件包，回滚记录格式不变。安装只维护目标确属已验证安装包、无额外参数且工作目录匹配的当前用户快捷方式；用户改过的同名链接保持原样。快捷方式失败不会撤销已经成功的安装，会显示重试提示。卸载默认保留配置和 Key；从 GUI 卸载时，由经校验的 CLI 等待窗口关闭后清理程序文件。
